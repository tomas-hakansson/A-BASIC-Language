ABL

User manual and language reference for A BASIC Language, by Tomas Håkansson and Anders Hesselbom.

Describes the project's implementation as of October 20, 2026. ABL is a Windows-based BASIC interpreter supporting a subset of Altair BASIC syntax. Limitations and deviations are stated explicitly.

1. Getting started and execution modes

The terminal serves as a program editor and handles commands, output and input. The menus open programs, start execution and change the display.

  1. Type NEW and press Enter for an empty program.
  2. Type 10 PRINT "HELLO!" and press Enter.
  3. Type 20 END and press Enter.
  4. Type LIST to display the program.
  5. Type RUN, choose Program → Run or press F5.

Direct mode, or immediate mode

When no program is running, a BASIC statement without a line number is executed immediately: PRINT 2+3, A=10 or A=10:PRINT A. Variables, arrays and user-defined functions persist between direct commands in the same session.

FOR I=1 TO 3:PRINT I:NEXT I can also run directly. FOR and NEXT must be in the same direct command; an incomplete loop cannot be continued with the next command.

However, ON … GOTO and ON … GOSUB require a numbered program line and are executed with RUN. These statements are not allowed in direct mode, including after a colon or in an IF branch.

Program memory and runtime

Lines with line numbers are stored rather than executed. RUN starts at the lowest line number and continues in numerical order unless a control statement changes the flow. Variables, arrays and user-defined functions are reset before every RUN.

During execution, INPUT accepts responses as data, not terminal commands. Ctrl+C interrupts execution. Normal termination displays Program has run through.. Direct commands, errors and interruptions normally end with Ready..

Values persist after execution and can be inspected using, for example, PRINT A. The next RUN resets them again. END and STOP do not delete values. NEW deletes both the program and its state.

2. Writing, editing and opening programs

Lines can be entered in any order. Numbers such as 10, 20, 30 leave room for additions. Colons separate statements on the same line. Move the cursor to a visible line, edit it and press Enter to store it again. Changing the line number creates a new line; delete the old one separately. LIST displays lines that are no longer visible.

Opening and saving files

File → Open from 101 BASIC Computer Games... opens a file dialog in the games' source folder. You can also select your own files. The filter is .bas or all files. The contents replace program memory and are listed; then execute RUN. Opening a file does not reset variables; RUN does so at startup.

Source files must contain numbered BASIC lines. Blank lines are allowed. Use unique line numbers. The program editor replaces duplicate numbers when loading, whereas the interpreter rejects duplicates if they occur in the source it receives.

ABL has no implemented save function. Create and save plain text with the .bas extension in an external text editor, then open it through the menu. Program memory is not saved automatically on exit.

3. Terminal commands outside runtime

Type without a line number and press Enter. Uppercase and lowercase are equivalent. RUN, LIST and NEW are session commands, not program statements. They cannot appear on numbered lines or be combined with BASIC statements using colons.

RUN

RUN

Resets variables, arrays and user-defined functions and runs the entire program. Takes no arguments: RUN 100 and filenames after RUN are not supported. The program source is retained. Before the program starts, the screen is cleared and the full text area is restored, as with WINDOW without an argument. An empty program returns to Ready.

LIST

SyntaxSelection
LISTAll stored lines.
LIST 100Only line 100, if it exists.
LIST 100-200From 100 through 200, inclusive.
LIST 100-Line 100 and higher.
LIST -200All lines up to and including 200.

Bounds are inclusive and need not correspond to existing lines. Spaces around the hyphen are allowed. LIST100 and LIST100-200 also work. Only non-negative 32-bit integers are accepted. A start greater than the end or invalid syntax produces ?Invalid LIST range. An empty selection prints no program lines. Values are unchanged.

NEW

NEW

Removes the entire program and all variables, arrays and user-defined functions without confirmation. The screen is cleared and the full text area is restored, as with WINDOW without an argument. Takes no arguments. There is no undo function.

Direct execution

Other text without a line number is sent to the BASIC interpreter. A standalone expression is not printed automatically: use PRINT 2+3. Text beginning with digits is normally treated as a program line.

Color themes

Type !COLORTHEME to display the short name of the currently selected theme. To change it, supply one of DEFAULT, C64, C128, VIC20 or C16. Theme names are case-insensitive.

!COLORTHEME C128
!COLORTHEME

The first command applies the Commodore 128 theme to the background, text (including existing text) and border. It also selects this theme as the default, which is saved when the application closes and loaded at the next startup. The second command displays C128.

An unknown theme name displays an error and the available short names without changing the colors or default theme. You can also select a theme in Tools → Options. Use the BASIC COLOR statement to change individual colors; it does not select a different default theme.

The parser accepts ON, YES, TRUE or 1 for on and OFF, NO, FALSE or 0 for off for FULLSCREEN, LOG and HQ-RENDER. ! commands are not BASIC statements.

6. Basic syntax, variables and types

10 REM EXAMPLE
20 A=5:PRINT A
30 END

A program line has a non-negative 32-bit line number and at least one statement. Numbers need not be consecutive. Blank physical lines are allowed in source files. A line number on its own in the terminal deletes the line. Colons separate statements.

Keywords and variables are case-insensitive. Spaces can often be omitted, as in FORI=1TO3, but clear spacing is recommended. The parser recognizes keywords and functions as prefixes. Avoid names beginning with PRINT, IF, FOR, FN, INT, ABS or other reserved words.

Names and types

ExampleTypeInitial value
A, X1, SCORENumeric without a suffix: double precision.0.
A%, COUNT%32-bit signed integer, −2147483648 to 2147483647.0.
A$, NAME$String.Empty string.

Names start with A–Z/a–z and continue with letters or digits. % or $ may end the name. Underscores and Swedish letters are not part of the naming grammar. The entire name is significant. A, A% and A$ are different variables. Declarations are not required; variables that have never been assigned return their initial value.

Assignment to % truncates the fractional part toward zero and checks the integer range. Numeric variables cannot be assigned strings, or vice versa. A="5" and A$=5 produce type errors.

Constants

Numbers use a decimal point: 12, 3.5, .5 and 2.. Exponent notation is supported: 1E3, 2.5E-2. Leading plus/minus signs are operators. Hexadecimal and octal formats are not supported. Output uses a decimal point.

Strings are enclosed in double quotes: "HELLO". An empty string is "". Neither escape sequences nor doubled quotes for embedded quotation marks are supported. Colons/commas inside strings are ordinary characters.

Arrays

A(3) is an array element; A is a separate scalar. Multiple subscripts and the suffixes % and $ are supported. Subscripts may be numeric expressions. DIM bounds are inclusive, starting at 0. See DIM for automatic creation.

7. Expressions and operators

Expressions are used in assignment, PRINT, conditions, loop bounds, subscripts and function arguments.

Precedence, highest firstOperatorMeaning
1(...), functionsSubexpressions.
2^Exponentiation, grouped from the right: 2^3^2 = 2^(3^2) = 512.
3Unary +, -Sign. -2^2 = −4; (-2)^2 = 4. 2^-2 is allowed.
4*, /Multiplication/division, left to right. Division by 0 produces an error.
5+, -Addition/subtraction, left to right. + also concatenates strings.
6=, <>, !=, <, >, <=, >=Comparisons. True = −1, false = 0. != is equivalent to <>.

Numeric equality uses a tolerance of 0.00001: A=B is true if the absolute difference is smaller, A<>B if it is larger. At exactly the tolerance boundary, both are false. Other comparisons use ordinary numeric bounds.

Strings are compared lexicographically using a case-insensitive ordinal comparison. "hello"="HELLO" and "10"<"2" are true. Comparing a string with a number produces a type error.

String addition deviation: + concatenates strings and numbers with text, but the current implementation reverses the operand order. "A"+"B" produces "BA"; "X"+2 produces "2X". Use PRINT expressions separated by semicolons when order matters. Numeric addition is unaffected.

AND, OR, NOT, MOD, integer division and bitwise operators are not supported. Use separate IF lines for compound conditions. 1<A<10 is not a range test: subsequent comparisons use the numeric result of the previous comparison.

8. Statement reference

These are all implemented program statements. ON … GOTO and ON … GOSUB may only be used in numbered program lines; other statements also work in direct mode with the limitations stated in their respective sections. Square brackets in the syntax indicate an optional part; do not type the brackets.

LET – assignment

[LET] variable = expression
[LET] array(index[,index ...]) = expression

Evaluates the right-hand side and stores the value. LET is optional. The suffix determines the target's type. Integer assignment truncates toward zero.

10 LET A=3.75
20 B%=-3.75
30 NAME$="ADA"
40 PRINT A;B%;NAME$

B% becomes −3. Assigning a number to a string or a string to a number produces a type error. Array subscripts must match the bounds and dimensions.

PRINT – output

PRINT
PRINT expression[;expression ...]
PRINT expression[,expression ...]

Without arguments, prints a blank line. Strings are printed without quotes. Numbers receive a leading space unless negative, and a trailing space. PRINT 4;2 therefore produces 4 2 .

SeparatorBehavior
;No extra padding; the numbers' own spaces remain.
,Next 14-character zone: one-based columns 15, 29, 43, etc. At a zone boundary, output moves to the next zone.
Trailing ; or ,No final line break. The next PRINT in the same run/direct command continues there.
 
10 PRINT "NAME";TAB(20);"SCORE"
20 PRINT "ADA";TAB(20);42
30 PRINT "PART 1 ";
40 PRINT "PART 2"

Separators can be mixed. TAB specifies an absolute column. Long lines wrap. A separate direct command receives a new terminal adapter; do not use trailing semicolons to continue output across several separate Ready commands.

INPUT – read values

INPUT variable[,variable ...]
INPUT "prompt";variable[,variable ...]

Prints an optional prompt, followed by ? , and waits for a response. The prompt must be a string constant followed by a semicolon. The target determines the type. Invalid numeric responses produce ?Redo from start and a new request for a numeric value. % truncates the fractional part toward zero.

10 INPUT "WHAT IS YOUR NAME";NAME$
20 INPUT "ENTER TWO NUMBERS";A,B
30 PRINT NAME$;": ";A+B

Each variable is read as a separate response followed by Enter. Enter A and press Enter, then B and Enter. Do not enter a comma-separated list. The statement prints the prompt and question mark once. Array elements may also be targets, for example INPUT A(2).

String responses do not require quotes; any quotes entered become part of the text. The terminal removes leading/trailing spaces. Use a decimal point; a comma is not treated as a Swedish decimal separator here. Numeric input uses culture-invariant .NET conversion and may accept exponent notation. Ctrl+C interrupts without assigning the interrupted response. Earlier assignments in the same INPUT list are not rolled back.

IF … THEN … ELSE – conditions

IF condition THEN statement[:statement ...] [ELSE statement[:statement ...]]
IF condition THEN lineNumber [ELSE lineNumber]

0 is false; other numeric values are true. The THEN branch runs if true, otherwise the optional ELSE branch runs. A numeric expression used as a branch is equivalent to GOTO with a calculated line number.

10 INPUT A
20 IF A>0 THEN PRINT "POSITIVE" ELSE PRINT "ZERO OR NEGATIVE"
30 IF A=0 THEN 100
40 PRINT "NONZERO":END
100 PRINT "ZERO":END

Branches cover the rest of the current BASIC line. In IF A THEN PRINT "YES":PRINT "ALSO", both PRINT statements run only when A is true. Put statements that should always run on the next line. Nested IF statements are not reliably supported; use separate lines and GOTO. Write LET explicitly in IF branches when assigning to %, $ and array elements to avoid limitations in the parser's recognition of the branch form.

GOTO and GO TO – jump

GOTO expression
GO TO expression

Continues from the specified program line. The expression is converted to an integer by truncating the fractional part. The line must exist; otherwise Undefined line is reported. Jumping into a FOR body without an active loop may produce a NEXT error. GOTO in direct mode cannot jump into program memory; start with RUN.

10 A=A+1
20 PRINT A
30 IF A<5 THEN 10
40 END

GOSUB and GO SUB – call a subroutine

GOSUB expression
GO SUB expression

Jumps to the specified program line and saves the next statement's position on the call stack. Unlike GOTO, this allows a return with RETURN. The expression must be numeric; the fractional part is truncated to an integer line number. The target must be between 0 and 2147483647, and the line must exist.

Calls can be nested, including recursively. Each RETURN returns from the most recent call. Variables are shared with the calling program. GOSUB in direct mode cannot call lines in the stored program; start with RUN.

10 GOSUB 100:PRINT "BACK":END
100 PRINT "SUBROUTINE"
110 GO SUB 200
120 RETURN
200 PRINT "NESTED CALL":RETURN

Prints SUBROUTINE, NESTED CALL and BACK in that order. END on line 10 prevents the main program from continuing straight into the subroutine.

RETURN – return from a subroutine

RETURN

Removes the most recent GOSUB call from the call stack and continues at the statement immediately after the call. That statement may follow a colon on the same line or be on the next program line. This also applies to calls through ON … GOSUB and the GO SUB spelling.

RETURN takes no arguments. If there is no active call, RETURN without GOSUB. is reported. RETURN ends a subroutine; use END or STOP to end the entire program.

ON … GOTO – select a jump target

ON expression GOTO lineNumber[,lineNumber ...]
ON expression GO TO lineNumber[,lineNumber ...]

May only be used in numbered program lines. The expression can contain numeric constants, variables, array elements and function calls. The value 1 selects the first line, 2 the second, and so on. Fractional values are rounded down. The value 0 or an index greater than the list's length continues with the next statement, including after a colon on the same line.

The list must contain at least one line number. Targets must be non-negative integer constants, not variables or calculations. Only the selected line number is checked when jumping: if the line is missing, Undefined line n. is reported. String values produce type errors, and negative or non-finite indices produce ON GOTO index is out of range..

10 X=2
20 ON X GOTO 100,200,300
30 PRINT "NO JUMP":END
100 PRINT "ONE":END
200 PRINT "TWO":END
300 PRINT "THREE":END

The example prints TWO. X=2.9 also selects line 200. Change to X=0 or X=4 to continue at line 30 and print NO JUMP.

The index could, for example, be A+1, ABS(A) or FNA(A). The expression is evaluated once when the statement executes. The target lines remain a fixed list.

10 ON 0 GOTO 100,200:PRINT "CONTINUING"
20 END
100 PRINT "ONE":END
200 PRINT "TWO":END

No jump occurs here, so PRINT after the colon executes. If the index is instead 1 or 2, the jump occurs immediately and PRINT on line 10 is skipped. Use ON … GOSUB for a call that can return with RETURN.

ON … GOSUB – select a subroutine

ON expression GOSUB lineNumber[,lineNumber ...]
ON expression GO SUB lineNumber[,lineNumber ...]

Selects a target using the same rules as ON … GOTO: the fractional part of a positive index is truncated, 1 selects the first line and 2 the second. Index 0 or a positive index outside the list continues to the next statement without pushing anything onto the call stack. Negative or non-finite indices produce ON GOSUB index is out of range.; strings produce type errors.

The target list must contain at least one non-negative integer constant. Variables and expressions are not allowed as targets in the list. Only the selected target needs to exist in the program. When a jump is selected, the return position is saved; RETURN continues after the entire ON statement. ON … GOSUB requires a numbered program line and cannot be used in direct mode.

10 X=2
20 ON X GO SUB 100,200
30 PRINT "BACK":END
100 PRINT "FIRST":RETURN
200 PRINT "SECOND":RETURN

Prints SECOND followed by BACK.

FOR … TO … STEP and NEXT – counting loops

FOR variable = start TO end [STEP step]
    statements
NEXT [variable]
NEXT variable1,variable2

The variable must be a numeric scalar. Start, end and step are evaluated once at FOR. The default step is 1; negative and fractional steps are allowed. STEP 0 produces an error. A positive step runs while the counter ≤ end, a negative step while the counter ≥ end. A start outside the range skips the body.

10 FOR I=1 TO 3
20 FOR J=2 TO 0 STEP -1
30 PRINT I;J
40 NEXT J,I
50 END

NEXT increments the counter and repeats if the bound permits. Without a name, it refers to the innermost loop. A list ends loops in the specified order, innermost first. FOR/NEXT must be properly nested and are matched before execution. Missing or incorrect pairs produce errors.

Name matching for NEXT preserves the source code's case; use the same spelling and case in FOR and NEXT.

If the body changes the counter, the next NEXT uses the new value. After normal completion, the counter has passed the bound by one step. Floating-point steps may cause rounding differences. The loop counter is stored as a floating-point number even for names ending in %; use names without a suffix for consistent loop behavior.

DIM – arrays

DIM A(maxindex)
DIM A(maxindex1,maxindex2,...),B$(maxindex),C%(maxindex)

Subscripts run from 0 through each bound, inclusive. DIM A(10) gives 11 elements; DIM B(2,3) gives 3×4. The initial value is 0 or an empty string. Bounds/subscripts may be expressions and are converted to integers by truncation toward zero. Negative bounds are invalid. Size is limited by memory and the integer calculation of the element count.

10 DIM A(3),NAME$(2)
20 A(0)=10:A(3)=40
30 NAME$(1)="ADA"
40 PRINT A(0);A(3);NAME$(1)

A new DIM with the same array name replaces the entire array and deletes its values. The scalar with the same base name is unaffected. The wrong number of subscripts or subscripts outside the existing bounds produce errors.

Without DIM, reading an array that has not yet been created returns the default value. The first assignment creates bounds based on the actual subscripts used: A(3)=7 creates an upper bound of 3, not a default bound of 10. The array does not grow automatically. Use DIM for explicit bounds. DIM A is accepted but creates no array and does not reset an existing scalar.

DEF FN – user-defined numeric functions

DEF FN name(parameter)=expression
FN name(argument)

One numeric parameter and a numeric result. DEF FNA(X)=X*X and DEF FN A(X)=X*X are equivalent; call FNA(3). Names/parameters follow the letter/digit rules but may not have % or $.

10 DEF FNA(X)=X*X+1
20 PRINT FNA(3)
30 END

Produces 10. The definition must have been executed before the call. A new definition replaces the old one. The parameter is local to the call; a global variable with the same name is unchanged. Other variables are read from the current global state at the time of the call. Functions can call one another; at most 256 simultaneous FN calls are allowed. The body is an expression, not program statements. String results and multiple parameters are not supported. Direct definitions persist between commands; RUN/NEW delete them.

WINDOW – text window

WINDOW [expression]

Clears the screen and selects how many of the terminal's 25 rows are used for text at the bottom. The number of text rows is always 25 before restriction, regardless of the terminal's pixel resolution. The argument specifies the number of rows to use, not the number of rows to leave free at the top.

Without an argument, WINDOW restores the full text area. An argument must be a numeric expression yielding an integer from 2 to 25. WINDOW 10 uses the bottom 10 rows and leaves the top 15 free of text. WINDOW 2 uses two rows; WINDOW 25 is equivalent to WINDOW without an argument. Variables and program memory are unaffected.

10 WINDOW 10
20 PRINT "TEXT IN THE BOTTOM 10 ROWS"
30 INPUT "PRESS ENTER";A$
40 WINDOW
50 PRINT "FULL TEXT AREA AGAIN"

The command works both in direct mode and in numbered programs. Every valid WINDOW call clears the screen before changing the text area. NEW and RUN also clear the screen and restore all 25 text rows; RUN does this before the program starts.

Values outside the range and fractional values produce WINDOW requires a whole number of text rows from 2 to 25.. String arguments produce type errors. An invalid argument does not change the text window or clear the screen.

30 COLOR 1,6
40 PRINT "GREEN"
50 COLOR 1,2

Works in direct mode and numbered programs, including IF branches. Text color changes affect subsequent output and input; existing text retains its foreground color. Background and border changes apply immediately to the screen. COLOR does not clear the screen or move the output position. The initial text color is White (2); background and border start as Black (1). The selected colors persist between direct commands and after program termination, and through RUN, NEW and WINDOW, until another COLOR changes it. COLOR 1,2 restores white text. COLOR 0,7 selects a blue background; COLOR 2,3 selects a red border.

A fractional, non-finite or out-of-range target produces COLOR requires a whole number from 0 to 2 for the target.. A fractional, non-finite or out-of-range color produces COLOR requires a whole number from 1 to 16 for the color.. String arguments produce type errors. Invalid arguments leave the current color unchanged.

RANDOMIZE – random number generator

RANDOMIZE

Replaces the interpreter instance's generator with a new .NET generator using default initialization. No seed argument is supported. A new generator is already created for each RUN or separate direct command. RANDOMIZE is therefore not required for random values. Normally use it at most once at the beginning, not before every RND.

REM – comment

REM any comment
10 A=1:REM THE REST OF THE LINE IS A COMMENT

Everything after REM on the same physical source line is ignored, including colons. An apostrophe as a comment marker is not supported.

END and STOP – terminate

END
STOP

Both terminate with the same behavior. STOP is not a resumable pause; CONT is unavailable. Variables are not deleted. Reaching the end of the last line also terminates execution, so END is optional.

9. Working built-in functions

These are all working built-in functions. Parentheses and one argument are required, except for RND, which can also be written without parentheses. Use numeric arguments. Some older conversion paths accept numeric text, but do not provide consistent type behavior across all functions.

ABS(x)

Absolute value. ABS(-7.5) returns 7.5. Numeric result.

PRINT ABS(-7.5)

EXP(x)

e raised to the power x using double precision. EXP(0) returns 1. Large positive arguments may produce Infinity; large negative arguments may produce 0 due to floating-point limits.

PRINT EXP(1)

INT(x)

32-bit integer conversion that truncates the fractional part toward zero. INT(3.9) returns 3 and INT(-3.9) returns −3. Differs from BASIC dialects where INT rounds down. Keep the argument within the integer range; outside it, ABL has no defined numeric behavior.

PRINT INT(3.9);INT(-3.9)

LOG(x)

Natural logarithm (base e) using double precision. The argument must be numeric and greater than 0; otherwise a runtime error is reported. LOG(1) returns 0 and LOG(EXP(1)) returns approximately 1. For the base-10 logarithm, use LOG(x)/LOG(10).

PRINT LOG(1);LOG(EXP(1))
PRINT LOG(100)/LOG(10)

RND and RND(x)

Pseudorandom floating-point number with 0 ≤ value < 1. RND is equivalent to RND(1). The argument is evaluated but its value is ignored: 0 does not reuse the previous value, and negative arguments do not specify a seed.

10 FOR I=1 TO 5
20 PRINT INT(6*RND)+1
30 NEXT I

Five dice rolls from 1–6. The generator's state is shared within a run, not between separate direct commands.

SQR(x)

Square root. SQR(9) returns 3. Negative arguments produce .NET's NaN, not a specific BASIC domain error. Check that the argument is non-negative yourself.

PRINT SQR(9)

TAB(n)

Intended for PRINT. Absolute one-based column: TAB(1) is the first column. n is converted to an integer by truncation toward zero; values less than 1 are treated as 1. A target before the current position first causes a line break. At the exact target position, no spaces are inserted.

10 PRINT TAB(5);"*";TAB(10);"*"

Stars in columns 5 and 10. Internally, TAB returns padding spaces and may print a line break while the expression is being evaluated. Use it as a separate PRINT expression with semicolons, not as a general string function. It does not change terminal width; targets beyond the screen wrap through normal output.

13. Scope and compatibility

This reference follows the active parser and interpreter. Older parser files and historical ambitions in the README do not define current support. Bundled game sources are sample material: a bundled file does not guarantee that all its language features are supported.

  • No full Altair BASIC compatibility. INT, RND, string addition and automatic array creation have the deviations described above.
  • DATA, READ and RESTORE have no implemented program statements.
  • WHILE/WEND, DO/LOOP, multiline IF blocks, ELSEIF and SELECT CASE are not supported.
  • LOAD, SAVE, MERGE, DELETE, RENUM, EDIT, CONT, CLEAR and CLS are not implemented terminal commands. Delete a line with a number on its own, or the entire program with NEW. Open files through the menu.
  • No implemented graphics, sound or cursor statements such as PLOT, DRAW, LINE, CIRCLE, SOUND, BEEP or LOCATE. COLOR supports background, text, and border colors. The resolutions' pixel dimensions are display modes, not a BASIC graphics API.
  • No BASIC file handling with OPEN, CLOSE, PRINT# or INPUT#.
  • No implemented PEEK/POKE, machine code, networking, process or system commands in the language.
  • No implemented INKEY$ or TIMER function.
  • No command-line support for a .bas file, automatic program execution or standalone BASIC compilation. Starting the application opens the Windows interface.
