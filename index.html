ABL

Användarmanual och språkreferens för A BASIC Language, av Tomas Håkansson och Anders Hesselbom.

Beskriver projektets implementation den 20 oktober 2026. ABL är en Windowsbaserad BASIC-tolk med ett urval av Altair BASICs syntax. Begränsningar och avvikelser anges uttryckligen.

1. Kom igång och körlägen

Terminalen används som programeditor och för kommandon, utskrift och inmatning. Menyerna öppnar program, startar körning och ändrar visningen.

  1. Skriv NEW och tryck Enter för ett tomt program.
  2. Skriv 10 PRINT "HEJ!" och Enter.
  3. Skriv 20 END och Enter.
  4. Skriv LIST för att visa programmet.
  5. Skriv RUN, välj Program → Run eller tryck F5.

Direktläge, eller immediate mode

När inget program körs utförs en BASIC-sats utan radnummer direkt: PRINT 2+3, A=10 eller A=10:PRINT A. Variabler, arrayer och egna funktioner består mellan direktkommandon i samma session.

Även FOR I=1 TO 3:PRINT I:NEXT I kan köras direkt. FOR och NEXT måste finnas i samma direktkommando; en ofullständig slinga kan inte fortsättas med nästa kommando.

ON … GOTO och ON … GOSUB kräver däremot en numrerad programrad och körs med RUN. Satserna är inte tillåtna i direktläge, heller inte efter kolon eller i en IF-gren.

Programminne och runtime

Rader med radnummer lagras i stället för att köras. RUN börjar vid lägsta radnumret och fortsätter i nummerordning om inte en kontrollsats ändrar flödet. Variabler, arrayer och egna funktioner nollställs före varje RUN.

Under körning tar INPUT emot svar som data, inte terminalkommandon. Ctrl+C avbryter. Normal avslutning visar Program has run through.. Efter direktkommandon, fel och avbrott visas normalt Ready..

Värden består efter körningen och kan undersökas med exempelvis PRINT A. Nästa RUN nollställer dem igen. END och STOP raderar inte värden. NEW raderar både program och tillstånd.

Rader kan skrivas i valfri ordning. Nummer som 10, 20, 30 lämnar plats för tillägg. Kolon skiljer satser på samma rad. Flytta markören till en synlig rad, ändra och tryck Enter för att lagra igen. Ändrat radnummer skapar en ny rad; radera den gamla separat. LIST visar åter rader som inte syns.

Öppna och spara filer

File → Open from 101 BASIC Computer Games... öppnar en fildialog i spelens källkodsmapp. Även egna filer kan väljas. Filtret är .bas eller alla filer. Innehållet ersätter programminnet och listas; kör sedan RUN. Filöppning nollställer inte variablerna; RUN gör det vid start.

Källfiler ska innehålla numrerade BASIC-rader. Tomma rader tillåts. Använd unika radnummer. Programeditorn ersätter dubbla nummer vid inläsning, medan tolken avvisar dubbletter om de förekommer i källan den får.

ABL har ingen implementerad sparfunktion. Skapa och spara vanlig text med ändelsen .bas i en extern texteditor och öppna via menyn. Programminnet sparas inte automatiskt vid avslutning.

3. Terminalkommandon utanför runtime

Skriv utan radnummer och avsluta med Enter. Stora och små bokstäver är likvärdiga. RUN, LIST och NEW är sessionskommandon, inte programsatser. De kan inte stå på numrerade rader eller kombineras med BASIC-satser via kolon.

RUN

RUN

Nollställer variabler, arrayer och egna funktioner och kör hela programmet. Tar inga argument: RUN 100 och filnamn efter RUN stöds inte. Programkällan består. Skärmen rensas och hela textytan återställs som med WINDOW utan argument före programstart. Ett tomt program återgår till Ready.

NEW

NEW

Tar bort hela programmet och alla variabler, arrayer och egna funktioner utan bekräftelse. Skärmen rensas och hela textytan återställs som med WINDOW utan argument. Tar inga argument. Ingen ångrafunktion finns.

Direkt körning

Övrig text utan radnummer skickas till BASIC-tolken. Ett fristående uttryck skrivs inte automatiskt ut: använd PRINT 2+3. Text som börjar med siffror behandlas normalt som en programrad.

6. Grundsyntax, variabler och typer

10 REM EXEMPEL
20 A=5:PRINT A
30 END

En programrad har ett icke-negativt 32-bitars radnummer och minst en sats. Nummer behöver inte vara sammanhängande. Tomma fysiska rader tillåts i källfiler. Ensamt radnummer i terminalen raderar raden. Kolon separerar satser.

Nyckelord och variabler är skiftlägesoberoende. Mellanslag kan ofta utelämnas, som i FORI=1TO3, men tydliga mellanslag rekommenderas. Parsern känner igen nyckelord och funktioner som prefix. Undvik namn som börjar med PRINT, IF, FOR, FN, INT, ABS eller andra reserverade ord.

Namn och typer

ExempelTypInitialvärde
A, X1, POANGNumerisk utan suffix: dubbelprecision.0.
A%, ANTAL%32-bitars signerat heltal, −2147483648 till 2147483647.0.
A$, NAMN$Sträng.Tom sträng.

Namn börjar med A–Z/a–z och fortsätter med bokstäver eller siffror. % eller $ får avsluta namnet. Understreck och svenska bokstäver ingår inte i namngrammatiken. Hela namnet är betydelsebärande. A, A% och A$ är olika variabler. Deklaration krävs inte; aldrig tilldelade variabler ger initialvärdet.

Tilldelning till % kapar decimaldelen mot noll och kontrollerar heltalsområdet. Numeriska variabler kan inte tilldelas strängar, eller tvärtom. A="5" och A$=5 ger typfel.

Konstanter

Tal använder punkt: 12, 3.5, .5 och 2.. Exponentnotation stöds: 1E3, 2.5E-2. Inledande plus/minus är operatorer. Hexadecimala och oktala format stöds inte. Utskrift använder punkt.

Strängar omsluts av dubbla citattecken: "HEJ". Tom sträng är "". Inga escapesekvenser eller dubblerade citattecken för inbäddade citattecken stöds. Kolon/komma inne i strängar är vanliga tecken.

Arrayer

A(3) är ett arrayelement; A är en separat skalär. Flera index samt suffixen % och $ stöds. Index får vara numeriska uttryck. DIM-gränser är inkluderande från 0. Se DIM för automatisk skapning.

7. Uttryck och operatorer

Uttryck används i tilldelning, PRINT, villkor, slinggränser, index och funktionsargument.

Prioritet, högst förstOperatorBetydelse
1(...), funktionerDeluttryck.
2^Potens, grupperas åt höger: 2^3^2 = 2^(3^2) = 512.
3Unärt +, -Tecken. -2^2 = −4; (-2)^2 = 4. 2^-2 tillåts.
4*, /Multiplikation/division, vänster till höger. Division med 0 ger fel.
5+, -Addition/subtraktion, vänster till höger. + även strängsammanfogning.
6=, <>, !=, <, >, <=, >=Jämförelser. Sant = −1, falskt = 0. != motsvarar <>.

Numerisk likhet använder toleransen 0,00001: A=B är sant om absolutdifferensen är mindre, A<>B om den är större. Precis vid toleransgränsen är båda falska. Övriga jämförelser använder vanliga numeriska gränser.

Strängar jämförs lexikografiskt enligt ordinal jämförelse utan skillnad mellan stora/små bokstäver. "hej"="HEJ" och "10"<"2" är sanna. Sträng jämförd med tal ger typfel.

Avvikelse i strängaddition: + sammanfogar strängar och tal med text, men den aktuella implementationen vänder operandordningen. "A"+"B" ger "BA"; "X"+2 ger "2X". Använd PRINT-uttryck med semikolon när ordningen är viktig. Numerisk addition påverkas inte.

AND, OR, NOT, MOD, heltalsdivision och bitoperatorer stöds inte. Skriv separata IF-rader för sammansatta villkor. 1<A<10 är inte ett intervalltest: senare jämförelser använder föregående jämförelses numeriska resultat.

8. Programsatsreferens

Detta är alla implementerade programsatser. ON … GOTO och ON … GOSUB får endast användas i numrerade programrader; övriga satser fungerar även i direktläge med de begränsningar som anges i respektive avsnitt. Hakparenteser i syntaxen betyder valfri del; skriv inte hakparenteserna.

LET – tilldelning

[LET] variabel = uttryck
[LET] array(index[,index ...]) = uttryck

Beräknar högerledet och lagrar värdet. LET är valfritt. Suffix avgör mottagarens typ. Heltalstilldelning kapar mot noll.

10 LET A=3.75
20 B%=-3.75
30 NAMN$="ADA"
40 PRINT A;B%;NAMN$

B% blir −3. Tal till sträng eller sträng till tal ger typfel. Arrayindex måste passa gränser och dimensioner.

PRINT – utskrift

PRINT
PRINT uttryck[;uttryck ...]
PRINT uttryck[,uttryck ...]

Utan argument skrivs en tom rad. Strängar skrivs utan citattecken. Tal får ett inledande blanktecken om de inte är negativa och ett avslutande blanktecken. PRINT 4;2 ger därför 4 2 .

AvskiljareBeteende
;Ingen extra utfyllnad; talens egna blanktecken består.
,Nästa 14-teckens zon: enbaserade kolumner 15, 29, 43 osv. Vid zongräns flyttas utskriften till nästa zon.
Avslutande ; eller ,Ingen slutlig radbrytning. Nästa PRINT i samma körning/direktkommando fortsätter där.
 
10 PRINT "NAMN";TAB(20);"POANG"
20 PRINT "ADA";TAB(20);42
30 PRINT "DEL 1 ";
40 PRINT "DEL 2"

Avskiljarna kan blandas. TAB ger absolut kolumn. För långa rader radbryts. Ett separat direktkommando får en ny terminaladapter; använd inte avslutande semikolon för fortsatt utskrift över flera separata Ready-kommandon.

INPUT – läs värden

INPUT variabel[,variabel ...]
INPUT "ledtext";variabel[,variabel ...]

Skriver valfri ledtext, därefter ? , och väntar på svar. Ledtexten måste vara en strängkonstant följd av semikolon. Typen bestäms av mottagaren. Ogiltiga numeriska svar ger ?Redo from start och ny begäran om numeriskt värde. % kapar decimaldelen mot noll.

10 INPUT "VAD HETER DU";NAMN$
20 INPUT "ANGE TVAA TAL";A,B
30 PRINT NAMN$;": ";A+B

Varje variabel läses som ett separat svar med Enter. Svara med A och Enter, sedan B och Enter. Skriv inte en kommaseparerad lista. Ledtext och frågetecken skrivs en gång av satsen. Även arrayelement kan vara mottagare, exempelvis INPUT A(2).

Strängsvar kräver inga citattecken; skrivna citattecken blir del av texten. Terminalen tar bort inledande/avslutande blanksteg. Använd punkt som decimaltecken; komma är inte en svensk decimalavskiljare här. Numerisk inmatning använder kulturinvariant .NET-konvertering och kan acceptera exponentnotation. Ctrl+C avbryter utan att tilldela det avbrutna svaret. Tidigare tilldelningar i samma INPUT-lista återställs inte.

IF … THEN … ELSE – villkor

IF villkor THEN sats[:sats ...] [ELSE sats[:sats ...]]
IF villkor THEN radnummer [ELSE radnummer]

0 är falskt; andra numeriska värden är sanna. THEN-grenen körs om sant, valfri ELSE-gren annars. Numeriskt uttryck som gren motsvarar GOTO till beräknat radnummer.

10 INPUT A
20 IF A>0 THEN PRINT "POSITIVT" ELSE PRINT "NOLL ELLER NEGATIVT"
30 IF A=0 THEN 100
40 PRINT "INTE NOLL":END
100 PRINT "NOLL":END

Grenarna gäller resten av aktuell BASIC-rad. I IF A THEN PRINT "JA":PRINT "OCKSAA" körs båda PRINT bara när A är sant. Lägg satser som alltid ska köras på nästa rad. Nästlade IF stöds inte tillförlitligt; använd separata rader och GOTO. Skriv LET uttryckligen i IF-grenar för tilldelning till %, $ och arrayelement för att undvika begränsningar i parserns identifiering av grenformen.

GOTO och GO TO – hopp

GOTO uttryck
GO TO uttryck

Fortsätter från angiven programrad. Uttrycket konverteras till heltal genom kapning av decimaldelen. Raden måste finnas, annars ges Undefined line. Hopp in i FOR-kropp utan aktiv slinga kan ge NEXT-fel. GOTO i direktläge kan inte hoppa in i programminnet; starta med RUN.

10 A=A+1
20 PRINT A
30 IF A<5 THEN 10
40 END

GOSUB och GO SUB – anropa subrutin

GOSUB uttryck
GO SUB uttryck

Hoppar till angiven programrad och sparar positionen för nästa sats på anropsstacken. Till skillnad från GOTO går det därför att återvända med RETURN. Uttrycket ska vara numeriskt; decimaldelen kapas till ett heltalsradnummer. Målet måste vara mellan 0 och 2147483647 och raden måste finnas.

Anrop kan nästlas, även rekursivt. Varje RETURN återvänder från det senast utförda anropet. Variabler är gemensamma med det anropande programmet. GOSUB i direktläge kan inte anropa rader i det lagrade programmet; starta med RUN.

10 GOSUB 100:PRINT "TILLBAKA":END
100 PRINT "SUBRUTIN"
110 GO SUB 200
120 RETURN
200 PRINT "NAESTLAT ANROP":RETURN

Skriver SUBRUTIN, NAESTLAT ANROP och TILLBAKA i den ordningen. END på rad 10 hindrar huvudprogrammet från att fortsätta rakt in i subrutinen.

RETURN – återvänd från subrutin

RETURN

Tar bort det senaste GOSUB-anropet från anropsstacken och fortsätter vid satsen direkt efter anropet. Satsen kan ligga efter kolon på samma rad eller på nästa programrad. Detta gäller även anrop via ON … GOSUB och stavningen GO SUB.

RETURN tar inga argument. Om inget aktivt anrop finns ges RETURN without GOSUB.. RETURN avslutar en subrutin; använd END eller STOP för att avsluta hela programmet.

ON … GOTO – välj hoppmål

ON uttryck GOTO radnummer[,radnummer ...]
ON uttryck GO TO radnummer[,radnummer ...]

Får endast användas i numrerade programrader. Uttrycket kan innehålla numeriska konstanter, variabler, arrayelement och funktionsanrop. Värdet 1 väljer första raden, 2 andra raden och så vidare. Decimaler avrundas nedåt. Värdet 0 eller ett index större än listans längd fortsätter med nästa sats, även efter kolon på samma rad.

Listan måste innehålla minst ett radnummer. Målen ska vara icke-negativa heltalskonstanter, inte variabler eller beräkningar. Endast det valda radnumret kontrolleras vid hoppet: saknas raden ges Undefined line n.. Strängvärden ger typfel och negativa eller icke ändliga index ger ON GOTO index is out of range..

10 X=2
20 ON X GOTO 100,200,300
30 PRINT "INGET HOPP":END
100 PRINT "ETT":END
200 PRINT "TVAA":END
300 PRINT "TRE":END

Exemplet skriver TVAA. Även X=2.9 väljer rad 200. Byt till X=0 eller X=4 för att fortsätta på rad 30 och skriva INGET HOPP.

Indexet kan exempelvis vara A+1, ABS(A) eller FNA(A). Uttrycket beräknas en gång när satsen utförs. Målraderna är fortfarande en fast lista.

10 ON 0 GOTO 100,200:PRINT "FORTSAETTER"
20 END
100 PRINT "ETT":END
200 PRINT "TVAA":END

Här sker inget hopp, så PRINT efter kolon körs. Om indexet i stället är 1 eller 2 sker hoppet direkt och PRINT på rad 10 hoppas över. Använd ON … GOSUB för ett anrop som kan återvända med RETURN.

ON … GOSUB – välj subrutin

ON uttryck GOSUB radnummer[,radnummer ...]
ON uttryck GO SUB radnummer[,radnummer ...]

Väljer mål enligt samma regler som ON … GOTO: decimaldelen av ett positivt index kapas, 1 väljer första raden och 2 den andra. Index 0 eller ett positivt index utanför listan fortsätter till nästa sats utan att lägga något på anropsstacken. Negativa eller icke ändliga index ger ON GOSUB index is out of range.; strängar ger typfel.

Mållistan måste innehålla minst en icke-negativ heltalskonstant. Variabler och uttryck tillåts inte som mål i listan. Bara det valda målet behöver finnas i programmet. Vid ett valt hopp sparas returpositionen; RETURN fortsätter efter hela ON-satsen. ON … GOSUB kräver en numrerad programrad och kan inte användas i direktläge.

10 X=2
20 ON X GO SUB 100,200
30 PRINT "TILLBAKA":END
100 PRINT "FOERSTA":RETURN
200 PRINT "ANDRA":RETURN

Skriver ANDRA och därefter TILLBAKA.

FOR … TO … STEP och NEXT – räknarslingor

FOR variabel = start TO slut [STEP steg]
  satser
NEXT [variabel]
NEXT variabel1,variabel2

Variabeln måste vara numerisk skalär. Start, slut och steg beräknas en gång vid FOR. Standardsteg är 1; negativa och decimala steg tillåts. STEP 0 ger fel. Positivt steg kör medan räknaren ≤ slut, negativt medan räknaren ≥ slut. Start utanför intervallet hoppar över kroppen.

10 FOR I=1 TO 3
20 FOR J=2 TO 0 STEP -1
30 PRINT I;J
40 NEXT J,I
50 END

NEXT ökar räknaren och upprepar om gränsen tillåter. Utan namn avses innersta slingan. En lista avslutar i angiven ordning, innerst först. FOR/NEXT måste vara rätt nästlade och matchas före körningen. Saknade eller felaktiga par ger fel.

Namnmatchningen för NEXT bevarar källkodens skiftläge; använd samma stavning och skiftläge i FOR och NEXT.

Ändrar kroppen räknaren används det nya värdet av nästa NEXT. Efter normal avslutning har räknaren passerat gränsen med ett steg. Flyttalssteg kan ge avrundningsskillnader. Slingräknaren lagras som flyttal även för namn med %; använd namn utan suffix för konsekvent slingbeteende.

DIM – arrayer

DIM A(maxindex)
DIM A(maxindex1,maxindex2,...),B$(maxindex),C%(maxindex)

Index går från 0 till och med varje gräns. DIM A(10) ger 11 element; DIM B(2,3) ger 3×4. Initialvärde 0 eller tom sträng. Gränser/index får vara uttryck och konverteras till heltal genom kapning mot noll. Negativa gränser är ogiltiga. Storleken begränsas av minne och heltalsberäkningen av antalet element.

10 DIM A(3),NAMN$(2)
20 A(0)=10:A(3)=40
30 NAMN$(1)="ADA"
40 PRINT A(0);A(3);NAMN$(1)

Ny DIM med samma arraynamn ersätter hela arrayen och raderar värdena. Skalären med samma grundnamn påverkas inte. Fel antal index eller index utanför befintliga gränser ger fel.

Utan DIM ger läsning från en ännu inte skapad array standardvärdet. Första tilldelningen skapar gränser utifrån just de använda indexen: A(3)=7 skapar gränsen 3, inte standardgräns 10. Arrayen växer inte automatiskt. Använd DIM för tydliga gränser. DIM A accepteras men skapar ingen array och nollställer inte en befintlig skalär.

DEF FN – egna numeriska funktioner

DEF FN namn(parameter)=uttryck
FN namn(argument)

En numerisk parameter och numeriskt resultat. DEF FNA(X)=X*X och DEF FN A(X)=X*X är likvärdiga; anropa FNA(3). Namn/parameter följer bokstavs-/sifferreglerna men får inte % eller $.

10 DEF FNA(X)=X*X+1
20 PRINT FNA(3)
30 END

Ger 10. Definitionen måste ha utförts före anropet. Ny definition ersätter gammal. Parametern är lokal för anropet; global variabel med samma namn ändras inte. Övriga variabler läses från aktuellt globalt tillstånd vid anropet. Funktioner kan anropa varandra; högst 256 samtidiga FN-anrop tillåts. Kroppen är ett uttryck, inte programsatser. Strängresultat och flera parametrar stöds inte. Direktdefinitioner består mellan kommandon; RUN/NEW raderar dem.

WINDOW – textfönster

WINDOW [uttryck]

Rensar skärmen och väljer hur många av terminalens 25 rader som används för text längst ned. Antalet textrader är alltid 25 före begränsning, oavsett terminalens pixelupplösning. Argumentet anger antal rader som ska användas, inte antal rader som ska lämnas fria överst.

Utan argument återställer WINDOW hela textytan. Ett argument ska vara ett numeriskt uttryck som ger ett heltal från 2 till 25. WINDOW 10 använder de nedersta 10 raderna och lämnar de översta 15 fria från text. WINDOW 2 använder två rader; WINDOW 25 motsvarar WINDOW utan argument. Variabler och programminne påverkas inte.

10 WINDOW 10
20 PRINT "TEXT I DE NEDERSTA 10 RADERNA"
30 INPUT "TRYCK ENTER";A$
40 WINDOW
50 PRINT "HELA TEXTYTAN IGEN"

Kommandot fungerar både i direktläge och i numrerade program. Varje giltigt WINDOW-anrop rensar skärmen innan textytan ändras. Även NEW och RUN rensar skärmen och återställer alla 25 textrader; RUN gör detta före programstart.

Värden utanför intervallet och decimaltal ger WINDOW requires a whole number of text rows from 2 to 25.. Strängargument ger typfel. Ett ogiltigt argument ändrar inte textfönstret och rensar inte skärmen.

RANDOMIZE – slumptalsgenerator

RANDOMIZE

Ersätter tolkinstansens generator med en ny .NET-generator med standardinitiering. Inget seedargument stöds. Ny generator skapas redan vid varje RUN eller separat direktkommando. RANDOMIZE krävs därför inte för slumpvärden. Kör normalt högst en gång i början, inte före varje RND.

REM – kommentar

REM valfri kommentar
10 A=1:REM RESTEN AV RADEN AER KOMMENTAR

Allt efter REM på samma fysiska källrad ignoreras, även kolon. Apostrof som kommentarstart stöds inte.

END och STOP – avsluta

END
STOP

Båda avslutar med samma beteende. STOP är ingen återupptagningsbar paus; CONT finns inte. Variabler raderas inte. Även slutet av sista raden avslutar, så END är valfritt.

9. Fungerande inbyggda funktioner

Detta är samtliga fungerande inbyggda funktioner. Parenteser och ett argument krävs, utom RND som också får skrivas utan parenteser. Använd numeriska argument. Vissa äldre konverteringsvägar accepterar numerisk text, men ger inget enhetligt typkontrakt över alla funktioner.

ABS(x)

Absolutbelopp. ABS(-7.5) ger 7.5. Numeriskt resultat.

PRINT ABS(-7.5)

EXP(x)

e upphöjt till x med dubbelprecision. EXP(0) ger 1. Stora positiva argument kan ge Infinity; stora negativa kan ge 0 på grund av flyttalsgränserna.

PRINT EXP(1)

INT(x)

32-bitars heltalskonvertering som kapar decimaldelen mot noll. INT(3.9) ger 3 och INT(-3.9) ger −3. Avviker från BASIC-dialekter där INT avrundar nedåt. Håll argumentet inom heltalsområdet; utanför det har ABL inget definierat numeriskt kontrakt.

PRINT INT(3.9);INT(-3.9)

LOG(x)

Naturlig logaritm (bas e) med dubbelprecision. Argumentet måste vara numeriskt och större än 0; annars ges ett körfel. LOG(1) ger 0 och LOG(EXP(1)) ger ungefär 1. För tiologaritmen används LOG(x)/LOG(10).

PRINT LOG(1);LOG(EXP(1))
PRINT LOG(100)/LOG(10)

RND och RND(x)

Pseudotillfälligt flyttal 0 ≤ värdet < 1. RND motsvarar RND(1). Argumentet beräknas men värdet ignoreras: 0 återanvänder inte föregående värde och negativa argument anger inget seed.

10 FOR I=1 TO 5
20 PRINT INT(6*RND)+1
30 NEXT I

Fem tärningsslag 1–6. Generatorns tillstånd delas inom en körning, inte mellan separata direktkommandon.

SQR(x)

Kvadratroten. SQR(9) ger 3. Negativa argument ger .NETs NaN, inte särskilt BASIC-domänfel. Kontrollera själv att argumentet är icke-negativt.

PRINT SQR(9)

TAB(n)

Avsedd för PRINT. Absolut enbaserad kolumn: TAB(1) är första kolumnen. n konverteras till heltal genom kapning mot noll; mindre än 1 behandlas som 1. Mål före aktuell position ger först radbrytning. Vid exakt målposition infogas inga blanksteg.

10 PRINT TAB(5);"*";TAB(10);"*"

Stjärnor i kolumn 5 och 10. TAB returnerar internt utfyllnadsblanksteg och kan skriva en radbrytning medan uttrycket beräknas. Använd som separat PRINT-uttryck med semikolon, inte som allmän strängfunktion. Ändrar inte terminalbredden; mål utanför skärmen radbryts genom vanlig utskrift.

Parsern känner igen nedanstående namn men tolken saknar implementation. Accepterade anrop ger Unsupported BASIC function: namn när de utförs. Betydelserna nedan är vanlig BASIC-betydelse som orientering, inte fungerande ABL-funktionalitet.

COSCosinus.

13. Omfattning och kompatibilitet

Referensen följer den aktiva parsern och tolken. Äldre parserfiler och historiska ambitioner i README definierar inte aktuellt stöd. Medföljande spelkällor är exempelmaterial: en medföljande fil garanterar inte att dess alla språkfunktioner stöds.

  • Ingen full Altair BASIC-kompatibilitet. INT, RND, strängaddition och automatisk arrayskapning har de avvikelser som beskrivits ovan.
  • DATA, READ och RESTORE saknar implementerade programsatser.
  • WHILE/WEND, DO/LOOP, flerradiga IF-block, ELSEIF och SELECT CASE stöds inte.
  • LOAD, SAVE, MERGE, DELETE, RENUM, EDIT, CONT, CLEAR och CLS är inte implementerade terminalkommandon. Radera rad med ensamt nummer, hela programmet med NEW. Öppna via menyn.
  • Inga implementerade grafik-, ljud-, färg- eller markörsatser såsom PLOT, DRAW, LINE, CIRCLE, SOUND, BEEP, COLOR eller LOCATE. Upplösningarnas pixelmått är visningslägen, inte ett BASIC-grafik-API.
  • Ingen BASIC-filhantering med OPEN, CLOSE, PRINT# eller INPUT#.
  • Inga implementerade PEEK/POKE-, maskinkods-, nätverks-, process- eller systemkommandon i språket.
  • Ingen implementerad INKEY$- eller TIMER-funktion.
  • Ingen kommandoradsfunktion för .bas-fil, automatisk programkörning eller fristående BASIC-kompilering. Programstart öppnar Windowsgränssnittet.

ABL är en tolk. Att bygga Windowsapplikationen från C# är en utvecklaråtgärd, inte en BASIC-kompilatorfunktion. Projektet riktar sig mot .NET Framework 4.8 och använder TerminalPixelMatrixLibrary.

Underlag och underhåll

Skärmredigering och tangenter följer den lokala källan till TerminalMatrixNetFramework och bör kontrolleras igen när biblioteket uppdateras.
